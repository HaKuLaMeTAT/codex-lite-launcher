# Codex Lite Launcher · Codex 轻启

非官方 Windows Codex 优化启动工具。通过按需创建窗口、减少页面预热和合并菜单刷新，降低不必要的后台开销；支持原位升级和独立优化副本，两种模式使用同一套优化。

**仅发布源码，不提供打包程序或修改后的 Codex 安装包。** 使用者需自行安装 Codex，并在本机应用补丁。本项目与 OpenAI 无隶属或背书关系。

## 性能优化点

| 优化 | 修改内容 | 取舍 |
|---|---|---|
| 宠物浮层 | 取消提前创建，保留正常打开路径 | 首次打开可能稍慢 |
| 快捷窗口 | 取消 Home/Thread 窗口预加载，按需创建 | 首次快捷键打开可能稍慢 |
| 分离窗口 | 取消备用窗口预加载，按需创建 | 首次分离可能稍慢 |
| 购买/充值页面 | 关闭两个预热条件，保留显式购买与充值入口 | 只有原本触发预热时才可能获益 |
| 应用菜单刷新 | 首次立即刷新，连续变化约每 250 ms 合并刷新 | 菜单更新可能等待一个周期；会话同步仍每次执行 |

### v0.5 新增：持续输出与刷新优化

| 优化 | 实现范围 | 边界 |
|---|---|---|
| 终端输出合并 | 空闲后的首块立即交付，其余按约 8 ms 合并；累计 64 Ki 字符提前交付，退出前刷新尾部 | 不丢弃输出；高频小块可能增加一个合并周期的等待 |
| 命令输出精确更新 | 仅对最新完整回合中已存在的命令项提供精确变更信息 | 历史回合、未完整加载、未知命令项及待确认终止提交沿用原更新路径 |
| 流式文字节点合并 | 将已经完成淡入动画的连续普通文本合并 | 链接、装饰、缺少稳定标识及仍在动画中的片段保持原渲染 |
| 代码语言识别复用 | 未指定语言的代码块复用最近识别结果；内容翻倍或替换时重识别，复用后停流一秒再校正 | 显式语言不变；卸载时清理额外定时器 |
| MCP 刷新合并 | 同一 QueryClient、主机和查询键的 ready 事件，首个立即处理，200 ms 窗口内重复事件补一次尾部刷新 | 不加入按缓存年龄跳过刷新的规则；失败、授权、连接变化和其他失效处理不变 |

v0.5 通过 AST 定位四个 JavaScript 模块中的修改点，不依赖固定字节偏移或混淆变量名。v0.6 将相同优化接入原位升级和独立副本两种模式。

新增优化以减少持续输出期间的重复处理为目标，尚无真实桌面性能收益数据；不宣称修复长期内存泄漏。

## 一台 Windows 电脑上的历史观察

2026-10-16，在同一台 Windows 电脑、同一 Codex 版本 `26.928.20755` 上，对优化前后进行过短时采样。机器有 8 个逻辑处理器、约 16 GiB 内存。下面只比较 `ChatGPT.exe` 桌面进程组，不包含后端与工具子进程。

| 指标 | 优化前 | 优化后 | 观察到的差异 |
|---|---:|---:|---:|
| 桌面进程数 | 13 | 10 | 减少 3 个 |
| 渲染进程数 | 6 | 3 | 减少 3 个 |
| 桌面进程私有内存合计 | 1,827.1 MiB | 1,185.5 MiB | 减少 641.6 MiB（35.1%） |
| 渲染进程私有内存合计 | 1,176.8 MiB | 566.8 MiB | 减少 610.0 MiB（51.8%） |
| 主进程私有内存 | 372.3 MiB | 386.7 MiB | 增加 14.4 MiB |
| 采样区间平均 CPU | 2.70% | 0.87% | 降低 1.83 个百分点 |

CPU 按累计 CPU 时间差计算，以 8 个逻辑处理器的整机总能力为 100%。内存采用私有内存口径；跨进程工作集包含共享页面，不作为独占物理内存节省量。

**这是一组历史观察，不是受控基准，也不是稳定收益承诺。** 优化前采样约 61 秒，应用已运行约 11–12 分钟；优化后采样约 30 秒，应用已运行约 4–5 分钟。两次均发生在交互诊断期间，未控制相同会话、操作及窗口状态，不能将全部差异归因于补丁，尤其不能据此承诺 CPU 降幅。

下降主要集中在渲染进程组，与减少隐藏窗口预加载的目标一致；主进程内存没有下降。该采样来自 v0.3 的原位补丁，v0.4 保留相同优化逻辑、改用独立副本交付；尚未对独立副本重新做同条件性能对照，也未验证长期内存增长。该历史数据不包含 v0.5 新增优化的收益。原始采样含本机进程等信息，仓库仅发布脱敏汇总，不上传原始日志。

## 使用源码

需要 Windows、Windows PowerShell 5.1 和 Node.js 20+，无需 `npm install`。当前只适配应用版本 **`26.928.20755`**；其他版本会拒绝处理。

```powershell
git clone https://github.com/HaKuLaMeTAT/codex-lite-launcher.git
cd codex-lite-launcher
.\启动补丁.cmd
```

1. 检查自动识别的来源安装；必要时点击“选择来源”。支持原版、保留可验证配套备份的 v0.3 安装，以及本工具已原位升级的安装。
2. 在顶部选择模式，再点击“检查来源”。

| 模式 | 操作 | 磁盘占用 |
|---|---|---|
| 原位升级 | 退出 Codex 桌面和 CLI，保留补丁窗口，点击“原位升级”；完成后按原方式启动 | 首次约需 1.02 GiB 可用空间，完成后约保留 0.51 GiB 回滚备份；界面显示实际估算 |
| 独立副本 | 选择尚不存在的目录，点击“生成副本”；退出其他 Codex 后，双击副本中的 `启动优化版.cmd` | 适配版本约 2.2 GiB，保留来源安装 |

原位升级同时替换 EXE 和 ASAR，不能只替换 EXE。升级前文件保存为同目录的 `.before-lite-v5` 配套备份，已有 `.before-perf-v3` 原始备份保留。撤回时，退出 Codex，在“原位升级”模式重新检查并点击“原位回滚”，恢复到本次升级前状态。不要删除配套备份。替换中途失败时保持 Codex 关闭，重新检查后回滚，不要启动半完成安装。

工具不会自动关闭或启动 Codex，也不修改快捷方式。原位操作会检查运行进程和可用空间。生成副本期间可以保持当前应用运行，但不要同时更新来源安装。默认副本输出为工具目录下的 `copies/Codex-optimized`，再次生成需使用新目录，不覆盖已有副本。失败时保留 `.building` 目录供检查，不应从该目录运行应用。

生成约需一份完整安装的磁盘空间（适配版本实测约 2.2 GiB），构建时还需数 GB 可用内存。生成工具依赖 Node.js，副本启动入口依赖 Windows PowerShell。入口只设置当前 PowerShell 进程执行策略，不修改全局策略，不自动提权。

## 独立范围与更新

独立的是应用文件，账户和设置仍使用默认位置，不复制用户数据。请通过附带入口启动，同一时刻只运行一个 Codex 桌面版本。入口使用 `--disable-features=NonBlockingOsClipboardReads` 参数，并在启动前核对 EXE/ASAR 与生成清单是否一致。

本工具没有改造应用内更新机制，也不自动追随新版。来源安装更新后，应重新检查支持情况并生成新副本；副本核心文件发生变化时，启动入口会停止并提示重新生成。保留原安装作为更新来源。

原位升级请通过工具配套替换，不要从副本挑选单个文件覆盖。应用更新可能覆盖原位优化；更新后需重新检查版本和兼容性，不能强行套用旧备份。停止使用副本时，退出后按原方式启动原安装即可；来源原本已打补丁的状态不会被恢复或改变。

## 兼容性与完整性

版本由 `patch.mjs` 的 `VERSION` 定义。未知版本、缺失/重复结构、摘要失效或不完整补丁会停止。没有固定整包哈希限制，但必须通过应用身份、版本、结构与摘要检查；不保证任意第三方补丁组合兼容。

对于已打 v0.3 补丁的来源，优先只读使用经过验证的 `.before-perf-v3` 配套原文件。旧原始备份已删除时，工具会验证 `.before-lite-v5` 升级前备份中的旧补丁结构和 EXE/ASAR 配套摘要，再追加新增优化，重建候选进行比对；检查、回滚、重新升级及生成副本不再依赖旧原始备份。尚未升级的 v0.3 安装也可通过同样验证后升级。更早版本或无法验证的安装仍拒绝处理。

回滚恢复的是 `.before-lite-v5` 中保存的升级前版本。如果它是 v0.3 补丁版，回滚后仍是 v0.3，不会恢复成官方原版。请保留这两份配套回滚文件；工具不会重建已删除的官方原始备份。

生成时复制运行文件（排除旧补丁备份），校验每个输出文件，并再次核对来源未变化；全部通过后才将 `.building` 改名为目标目录。`codex-optimized-copy.json` 清单用于一致性检查，不是数字签名。暂不支持含链接的来源。

ASAR 重建只改变四个目标模块、对应摘要和必要偏移，保留其他内容及 unpacked 元数据。EXE 精确更新 `INTEGRITY/ELECTRONASAR` 资源中的 64 字节头部 SHA-256，不关闭完整性校验开关。修改 EXE 不能保留原始 Authenticode 签名有效性，本工具不重签名。

## 开发与验证

以下路径均为示例，请替换为自己的安装路径：

```powershell
node .\copy.mjs inspect 'C:\Apps\Codex\app\resources\app.asar'
node .\copy.mjs create 'C:\Apps\Codex\app\resources\app.asar' 'C:\Apps\Codex-optimized'
node .\copy.mjs verify 'C:\Apps\Codex-optimized'
node .\inplace.mjs inspect 'C:\Apps\Codex\app\resources\app.asar'
# apply/restore 前完全退出 Codex 桌面和 CLI。
node .\inplace.mjs apply 'C:\Apps\Codex\app\resources\app.asar'
node .\inplace.mjs restore 'C:\Apps\Codex\app\resources\app.asar'
node --test .\test\patch.test.mjs

# 额外只读验证真实安装和配套原文件；未设置时真实包测试显示 skipped。
$env:CODEX_TEST_ASAR = 'C:\Apps\Codex\app\resources\app.asar'
node --test .\test\patch.test.mjs
```

旧 `patch.mjs` 命令保留 v0.3 算法供维护旧补丁；新原位升级和回滚使用 `inplace.mjs`，界面按所选模式调用对应后端。`build` 只输出核心文件，不是完整应用。

已完成的验证与尚未覆盖的范围见 [VALIDATION.md](VALIDATION.md)。完整桌面验收仍需覆盖首次窗口打开、焦点、语音、分离与恢复、购买/充值、菜单与快捷键、截图粘贴及图像输入。
